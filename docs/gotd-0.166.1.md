# gotd v0.166.1

Обновление с v0.166.0 на [v0.166.1](https://github.com/gotd/td/releases/tag/v0.166.1),
commit `a45380bcabc7d60a05077ae7a960722fb294233f`.
[Полное сравнение](https://github.com/gotd/td/compare/v0.166.0...v0.166.1).

## Что меняется

После истечения server salt Telegram может отклонить ping через
`bad_server_salt`. В прежней версии соль обновлялась при повторе RPC;
у ping такого обработчика нет. Потерянная соль приводила к ожиданию pong
и лишнему переподключению. Теперь новая соль сохраняется при обработке
отказа независимо от вида сообщения, а ожидающий ping отправляется снова.
Обновление затрагивает обычный ping и ping с отложенным отключением.
Тайм-аут и отмена контекста сохранены.

В upstream добавлен синтетический `TestPingResentAfterBadServerSalt`.
Отдельная правка `telegram/dc_transfer_test.go` ждёт сохранения ключа DC
перед его удалением в тесте; рабочий код переноса DC не изменён.

Это исправление применимо к нашему постоянному соединению службы.
Оно не доказывает причину любого ранее замеченного зависания чтения:
для такого вывода нужна трассировка конкретного запроса.

## Схема и интерфейс агентов

Побайтово сравнены модульные исходники обеих версий:

- `_schema/telegram.tl` совпадает;
- `tg/tl_registry_gen.go` совпадает, `Layer = 233`;
- upstream `go.mod` совпадает.

В сравнении релизов изменены только шесть файлов: пять в `mtproto/`
и тест переноса DC. Новых типов медиа, сообщений, действий и методов
Telegram нет. Публичный интерфейс клиента, наш запуск, хранилище сессии
и интерфейс MCP сохраняются; новой функции агентам добавлять не требуется.

## Проверка выпуска

Штатный выпуск: отдельное ревью зависимости, полный
`scripts/build-worker.ps1` на worker (тесты, vet, три exe и DLL), проверка
манифеста и сохранённых прежних файлов при локальном вводе, затем чтение
`saved` через работающую службу. Сбой соли на живой сессии намеренно
не вызывается; успешное чтение само по себе не проверяет эту ветку.
