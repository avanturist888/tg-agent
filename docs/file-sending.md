# Отправка файлов и ожидание результата

## Статус во время большой отправки

При работающей службе ожидание решения читает состояние черновика и не
входит в SendDue. Mutex отправителя может удерживаться на протяжении
всей загрузки пачки; наблюдателю этот mutex не нужен. Свой срок наблюдения
не отменяет и не перезапускает отправку службы. Явный timeout_sec ограничивает
и ожидание автоотправки, а не повышается до задержки плюс минута.

При истечении срока возвращается текущий scheduled/sending. Повторяется
проверка того же draft_id, а не создание сообщения. Самостоятельный путь
без службы по-прежнему умеет разбирать кнопки и досылать очередь.

Списки черновиков нескольких аккаунтов остаются сгруппированы в accounts.
Ошибки валидации и отдельных аккаунтов сохраняются как error/message,
агрегат отмечается IsError, успешные части не пропадают. Подсказка списка
черновиков больше не описывает список чатов. Поля chat у tg_list_drafts нет.

## Аудиотреки Telegram

MP3/M4A/M4B при обычном прикладывании отправляются как audio. as_files=true
оставляет документ. Размер и секретность проверяются тем же механизмом
снимков, что у остальных вложений. MAX и WhatsApp этим режимом не меняются.

Для плеера используется
[DocumentAttributeAudio](https://core.telegram.org/constructor/documentAttributeAudio)
с длительностью, названием и необязательным исполнителем; Voice выключен,
ForceFile не задаётся. ffprobe из FFmpeg читает длительность и title/artist
из локального снимка; без title используется исходное имя без расширения.
Процесс ограничен 15 секундами, не получает shell и сетевых протоколов,
на Windows запускается без окна. ffprobe должен быть установлен в PATH.
Отказ извлечения метаданных происходит до загрузки/отправляющего RPC.

Треки отправляются по одному с сохранением их порядка в списке. Это выбор
простого существующего пути, а не ограничение Telegram на аудиоальбомы.
При частичном сбое сохраняются ID уже отправленного; общий механизм не
повторяет такую пачку автоматически.

## Уборка проверочного файла

Команда владельца `tg cleanup-saved-file <draft_id>` удаляет ровно одно
сообщение одного файла без отдельного текста, отправленное этим шлюзом
в его Избранное за последний час. Проверяются status=sent, message_id,
число файлов, отсутствие опроса/голоса/правки/BotFather, can_send и target=self.
Контейнеры и другие сети не допускаются. Выполнение — только через службу;
общего MCP-инструмента удаления не добавлено. Команда применяется по прямому
поручению владельца, в том числе для уборки разрешённого теста.

Это не реализация общего удаления сообщений из других чатов. Исходные
черновики остаются историей отправки, удаления отмечаются отдельно в аудите.
