# Доставка заданий о новых версиях

Задание агенту и карточка владельцу — независимые результаты. В SQLite `kv`
под ключом `upstream_notices` хранится последнее событие каждого источника:
текст задания, его поколение, приём агентским транспортом, состояние карточки
и решение ack/escalate. Запись создаётся до внешних вызовов. Новая схема
базы или отдельный процесс доставки не требуются.

Сначала вызывается существующий маршрут Нестора в назначенный тред.
Недоступность Bot API не препятствует этому вызову. Пометка «Задание
передано агенту» появляется после успешного ответа транспорта; она не
утверждает, что модель прочитала письмо. При недоступном маршруте карточка
идёт владельцу, а задание остаётся на повтор. Подмена треда и создание
нового треда при ошибке запрещены прежним правилом.

Проверка источников остаётся ежечасной. Сохранённые незавершённые доставки
служба повторяет раз в минуту, в том числе после перезапуска, независимо
от нового изменения источника. У показа карточки общий бюджет 15 секунд;
остаток работы сохраняется. Известный ID позволяет править прежнюю карточку.
Потерянный ответ Bot API без ID остаётся неизвестным результатом: повтор
может создать ещё одну карточку. У Bot API и общего mailbox нет общего
exactly-once подтверждения; потерянный ответ приёма задания тоже может
привести к повторной передаче после сбоя процесса.

Ack/escalate сначала записываются в базу и доступны даже до появления
карточки. Поколение события защищает от завершения нового события старым
снимком. Запоздалый ответ карточки перечитывает решение и показывает итог,
не открывая задачу снова. Последний завершённый идентификатор сохраняется,
чтобы повтор проверки после сбоя записи состояния источника не восстановил
уже разобранное событие. Ранее созданные карточки обслуживаются прежним
совместимым путём.

Поколение включает предыдущее сохранённое наблюдение источника: повтор после
сбоя записи сохраняет идентичность, а новая такая же авария после восстановления
получает новое событие. Явный incident report также означает новое происшествие.
Незавершённое снятие старой карточки переносится при замене даже после ack;
ошибка очистки оставляет её на повтор.

Для совместимости хранится снимок строки `upstream_cards`, записанной новым
кодом. Перед чтением/изменением он сверяется с фактической таблицей в транзакции.
Если прежняя сборка либо rollback-импорт удалили строку, событие считается
завершённым; если изменили или заменили её, управление переходит совместимой
строке. Старый KV не перекрывает более новое решение прежней сборки.

Новые проверки используют только временные базы и подставные Bot API/mailbox:
отказ бота, отказ mailbox, повтор без нового изменения, ранний ack, ack во
время send/pin, эскалацию без карточки, старое поколение и отсутствие бота.
