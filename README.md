# tg-agent

Доступ агентов Claude Code к Telegram — только к тем чатам, которые ты сам
разрешил, и без права отправить что-либо без твоего подтверждения.

- MCP-сервер `telegram` с инструментами `tg_read_chat`, `tg_search_chat`,
  `tg_draft_message`, `tg_send_draft` и т.д.
- Белый список чатов в `config/chats.toml` — всё остальное для агента не существует.
- Отправка — кнопкой в Telegram: агент готовит черновик, тебе в бот прилетает
  карточка с точным текстом и кнопками «Отправить» / «Отклонить».
- Картинки агент видит сам (`tg_view_media`), любые вложения — включая видео
  целиком — скачивает в `data/downloads/` (`tg_download_file`), а файлы может
  отправлять вместе с сообщением: они приходят тебе в бот рядом с карточкой.
- Реакции агент ставит сразу, без одобрения, но только в чатах с `send = true`;
  каждая пишется в аудит, выключаются целиком `TG_REACTIONS=off` в `.env`.
- Подписка на чаты: демон раз в ~10 с дописывает id новых сообщений в
  `data/feeds/<alias>.ids`, агенты следят за файлом (`tg watch <alias>` через
  Monitor) и не опрашивают Telegram сами. Частота — `TG_FEED_INTERVAL` в `.env`.
- Голосовые и кружки агент получает расшифрованными — встроенной функцией
  Telegram (Premium), с кэшем в `data/transcripts.json`.
- Сессия Telethon лежит локально в `data/`, аудит всех действий — в `data/audit.jsonl`.
- Инструкция для агентов: [AGENTS.md](AGENTS.md).

## Шпаргалка: открыть агенту новый чат

```powershell
cd <tg-agent>

# 1. найти чат по куску названия (ссылка не нужна, видно и приватные, и архивные)
uv run tg dialogs --filter "рабоч"

# 2. открыть доступ: без --send это только чтение
uv run tg allow work-team --match "Рабочая группа" --send

# 3. проверить, что агент теперь видит
uv run tg chats
```

Дальше агенту достаточно сказать словами: «посмотри, что нового в work-team»,
«найди в work-team про деплой», «напиши в work-team, что релиз готов». Алиас из
шага 2 — это и есть имя, которым он обращается к чату.

Поменять права у уже добавленного чата — та же команда без `--id`/`--match`.
Права задаются целиком: без `--send` отправка выключается.

```powershell
uv run tg allow work-team --send   # чтение + отправка
uv run tg allow work-team          # только чтение
```

Закрыть доступ совсем — убрать блок `[[chat]]` из `config/chats.toml`.
Перезапускать ничего не нужно.

## Установка

### 1. Ключи приложения

Зайти на https://my.telegram.org → **API development tools** → создать приложение.
Получишь `api_id` и `api_hash`. Вписать в `.env` (он уже создан из `.env.example`):

```dotenv
TG_API_ID=1234567
TG_API_HASH=0123456789abcdef0123456789abcdef
TG_PHONE=+7...
```

Остальное в `.env` можно не трогать. Отдельного бота заводить не нужно:
можно переиспользовать бота, который уже шлёт тебе уведомления (например, о хуках
Claude Code): по умолчанию токен и chat_id читаются из
`~/.local/share/cc-telegram-notify/config.env` (`NOTIFICATIONS_BOT_TOKEN`,
`NOTIFICATIONS_CHAT_ID`). Другой путь — `TG_BOT_ENV_FILE`, либо впиши
`TG_BOT_TOKEN` и `TG_APPROVAL_CHAT_ID` прямо в `.env`.

### 2. Логин (один раз)

```powershell
uv run --directory <tg-agent> tg login
```

Telegram пришлёт код в приложение, при включённой двухфакторке спросит ещё и
пароль. После этого в `data/user.session` лежит сессия — заново логиниться не
нужно, даже после перезагрузки.

> `data/user.session` = полный доступ к аккаунту. Не коммитить, не копировать,
> не отдавать. Отозвать: `uv run tg logout` или в приложении Telegram →
> Настройки → Устройства (сессия называется `tg-agent`).

### 3. Белый список чатов

Посмотреть, что вообще есть в аккаунте, и взять id:

```powershell
uv run --directory <tg-agent> tg dialogs --filter работа
```

Публичная ссылка для этого не нужна — id берётся из твоей сессии, так что
приватные группы, архивные чаты, личка и боты видны наравне со всеми. `--filter`
ищет регистронезависимую подстроку в названии; если чат далеко в списке, подними
`--limit` (по умолчанию 200).

Добавить найденное можно одной командой, не трогая TOML:

```powershell
uv run --directory <tg-agent> tg allow work-team --match "Рабочая группа" --send
```

Без `--send` чат добавляется только на чтение. Если под `--match` подходит
несколько чатов, команда покажет их и попросит уточнить.

Либо вписать руками в `config/chats.toml`:

```toml
[[chat]]
alias = "work-team"       # этим именем агент обращается к чату
id = -1001234567890       # id из `tg dialogs`; годится и "@username", и "me"
title = "Рабочая группа"
read = true               # можно читать
send = false              # писать нельзя
note = "Только чтение задач"
```

Файл перечитывается на каждом вызове — перезапускать Claude Code после правок не надо.

Проверить настройку целиком:

```powershell
uv run --directory <tg-agent> tg doctor
```

### 4. Подключить MCP-сервер к Claude Code

Уже сделано в user scope — сервер виден во всех проектах:

```powershell
claude mcp add --scope user telegram -- uv run --directory <tg-agent> tg-mcp
```

Только в одном проекте — положить рядом с проектом `.mcp.json` (готовый образец:
[`.mcp.json.example`](.mcp.json.example)).

Проверить: в сессии Claude Code выполнить `/mcp` — должен быть сервер `telegram`
со статусом connected.

### 5. Слушатель кнопок в автозапуск

```powershell
powershell -ExecutionPolicy Bypass -File <tg-agent>\scripts\install-approvals-task.ps1
```

Ставит задачу `tg-agent-approvals`: запуск при входе в систему, перезапуск после
сбоя, без окна консоли. Она и разбирает нажатия кнопок в боте.

Без неё тоже работает, но хуже: нажатие обрабатывается, только пока какой-нибудь
агент ждёт решения. Нажал позже — сработает лишь когда кто-то снова начнёт ждать
или ты выполнишь `tg approvals --once`. `tg doctor` показывает, запущен слушатель
или нет.

## Команды владельца

```
tg login                     вход и сохранение сессии
tg logout                    отозвать сессию на стороне Telegram
tg whoami                    под каким аккаунтом работаем
tg dialogs [--filter x]      все диалоги (вкл. архив) — искать чат по имени
tg allow <alias> --match x   найти чат по имени и добавить в белый список
tg allow <alias> --id -100…  то же, но по готовому id
tg chats [--status]          что разрешено агентам (+ непрочитанные)
tg read <alias> [--limit N] [--search x]
tg drafts [--status pending] очередь черновиков от агентов
tg pending                   что ждёт нажатия кнопки
tg approvals [--once]        слушатель кнопок: демон или разбор накопившегося
tg approve <id> [--send]     подтвердить отправку
tg reject <id>               отменить черновик
tg send <id>                 отправить подтверждённый черновик вручную
tg doctor                    проверить конфигурацию
```

Все запускаются как `uv run --directory <tg-agent> tg <команда>`.
Изнутри сессии Claude Code удобно префиксом `!` — команда выполнится от тебя, а
не от агента.

## Как выглядит отправка сообщения

1. Агент вызывает `tg_draft_message`. Ничего не уходит, но тебе в бот прилетает
   карточка:

   > 🤖 **Агент просит отправить сообщение**
   > Чат: **Рабочая группа** (`work-team`)
   > Повод: отчёт о деплое из проекта my-service
   >
   > ───
   > **Деплой прошёл**, версия `1.4.2`
   > [ ✅ Отправить ] [ ✋ Отклонить ]

   Шапка отделена разделителем, а под ним — сообщение уже отрисованным, ровно
   так, как уйдёт. Агенты пишут в Markdown, отправка идёт через rich messages
   (Telegram, июнь 2026): заголовки, списки, таблицы, цитаты, блоки кода
   рисуются в чате как есть, и от твоего аккаунта тоже. Если сервер rich-формат
   не примет, сообщение уйдёт обычной markdown-разметкой (в аудите
   `format: markdown_fallback` и причина). `format="plain"` — текст без разметки.

2. Жмёшь кнопку.
   - **Отправить** — сообщение уходит от твоего аккаунта, карточка тут же
     переписывается на «✅ Отправлено в «Рабочая группа» в 18:42 (id 10235)».
   - **Отклонить** — «✋ Отклонено», ничего не ушло.

3. Агент видит результат через `tg_wait_approval` и работает дальше. Если ты не
   нажал за `TG_APPROVAL_TIMEOUT_SEC` (10 минут), агент получает `waiting` и не
   висит дальше — карточка при этом остаётся живой, нажатие сработает и через час.

Если агент прикладывает файлы, они приходят в бот отдельными документами прямо
перед карточкой, а в шапке карточки перечислены с размерами. Файлы больше 50 МБ
бот показать не может (ограничение Bot API) — в карточке у них пометка «не
показан». Уходят файлы документами, без пережатия. При создании черновика с них
снимается копия, и после нажатия уходит именно она — агент не может подменить
файл между твоим одобрением и отправкой. Файлы из папки tg-agent, `.env`, ключи
и сессии к отправке не принимаются вовсе. Пределы — `TG_MAX_FILE_MB` (отправка)
и `TG_MAX_DOWNLOAD_MB` (скачивание) в `.env`.

Кнопки слушаешь только ты: нажатие с чужого user id отклоняется, попытка пишется
в аудит. Повторное нажатие на уже обработанной карточке ничего не делает.

Запасные пути, когда бот недоступен: `tg pending` — что ждёт решения,
`tg approve <id> --send` — подтвердить и отправить из терминала, `tg reject <id>` —
отказать. `tg approvals --once` разбирает нажатия, накопившиеся пока слушатель не
работал (Telegram хранит их сутки).

Неподтверждённые черновики протухают через `TG_DRAFT_TTL_MIN` минут (по умолчанию 60).

### Режимы отправки (`TG_SEND_POLICY` в `.env`)

| Режим | Что требуется для отправки |
|---|---|
| `bot_approval` | кнопка под карточкой в боте (по умолчанию) |
| `human_approval` | команда `tg approve <id>` в терминале |
| `agent_confirm` | согласие в диалоге; агент передаёт его дословно |
| `disabled` | ничего, отправка выключена — только чтение |

## Границы доступа

Что агент **не может**:

- прочитать или найти чат, которого нет в `config/chats.toml`;
- получить список всех твоих диалогов (`tg dialogs` — только из CLI, не из MCP);
- написать в чат с `send = false` или при `TG_SEND_POLICY=disabled`;
- отправить сообщение без подтверждения;
- скачивать медиа — файлы и картинки видны только как пометка `media`.

Что стоит держать в голове: прочитанное агентом попадает в контекст модели.
Для чатов с секретами лучше не давать доступ вовсе. И `.env`, и `data/` уже в
`.gitignore` — не выноси их в репозиторий.

## Как оно устроено

```
src/tg_agent/
  config.py   .env + белый список, резолв alias → чат
  client.py   Telethon: подключение на время запроса, чтение, отправка
  service.py  проверки прав, единая логика для CLI и MCP
  outbox.py   черновики и их подтверждение
  mcp_server.py  MCP-сервер (stdio) — то, что видит агент
  bot.py      Bot API: карточки и кнопки, с запасным маршрутом через SOCKS5
  approvals.py long-polling кнопок, обработка нажатий, ожидание решения
  cli.py      команды владельца
  lock.py     межпроцессные локи: файл сессии и «кто слушает кнопки»
  audit.py    журнал в data/audit.jsonl
```

Сессия Telethon — это SQLite, а MCP-сервер поднимается в каждом проекте своим
процессом. Поэтому соединение живёт только на время запроса и берётся под
файловым локом: параллельные агенты не дерутся за сессию. Плата — около секунды
на подключение при каждом вызове.

Апдейты бота Telegram отдаёт ровно одному потребителю, поэтому `getUpdates`
берётся под локом `data/bot-updates.lock`. Кто его держит — тот и разбирает
нажатия: обычно демон, а если он не запущен, роль на время ожидания берёт сам
агент. Отсюда же `tg doctor` знает, работает слушатель или нет.
