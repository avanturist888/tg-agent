# tg-agent

Проект даёт агентам Claude Code доступ к Telegram владельца, ограниченный белым
списком чатов.

- Правила работы с Telegram для агента: **[AGENTS.md](AGENTS.md)** — читать перед
  первым вызовом любого `tg_*` инструмента.
- Установка, команды владельца, устройство: [README.md](README.md).

Работая над кодом этого проекта:

- Зависимости и запуск — только через `uv` (`uv run tg ...`), глобальный Python заперт.
- `.env`, `data/` (сессия, аудит, черновики) и `config/chats.toml` — приватные,
  не коммитить, не показывать в выводе, не копировать в другие места.
- Любое ослабление проверок в `service.py`/`approvals.py` (белый список,
  подтверждение отправки, проверка чужих нажатий) — только по прямой просьбе владельца.
- Токен бота берётся из чужого `config.env` (`cc-telegram-notify`) — не копируй
  его в этот репозиторий и не печатай в выводе.
- Слушатель кнопок — задача Планировщика `tg-agent-approvals`; после правок в
  коде её нужно перезапустить, иначе крутится старый код. `Stop-ScheduledTask`
  НЕ убивает дочерний python — добивать процессы с `tg.exe" approvals` в
  командной строке через `Stop-Process`, потом `Start-ScheduledTask`. Локи
  убитых процессов снимаются сами (проверка, жив ли pid-владелец). Если
  слушателя убили между нажатием «Отправить» и отправкой, новый при старте
  дошлёт такой черновик сам (`recover_interrupted`).
- Id карточки брать из черновика (`bot_message_id`): под rich-сообщением
  callback приходит без `message`. Id сообщений в личке у бота и у
  пользовательского аккаунта разные — искать карточку со стороны Telethon по
  содержимому, а не по id.
