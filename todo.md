Отложенные задачи проекта. Взял — сделай, вычеркни (удали пункт) в том же

- Ограничить ожидание карточки при создании черновика и возвращать агенту
  уже сохранённый draft_id/достоверный свежий статус. В случае RC сообщение
  ушло через автоотправку, но ответ tg_draft_message оставался в Notify
  до отмены клиента: Bot API допускает долгие сетевые повторы. Не заставлять
  агента гадать о результате или повторять создание. Карточку и её неизвестный
  исход обрабатывать отдельно; отказ карточки не должен выдавать согласие
  на ручную отправку или ослаблять подтверждение. Проверить auto/manual,
  отмену, уже ушедший черновик и запоздалый ответ Bot API на fixtures.
- Убирать устаревшие ещё не доставленные уведомления подписки при явном
  продвижении отметки агентом. Разбор RC подтвердил: принятые Нестором
  текстовые письма могут уйти в T3 после обработки сообщений и записи
  нового cursor; это не откат cursor. У общего inbox пока нет producer
  replace/invalidate/dedupe/generation API — подтверждено его владельцем.
  Подключение требует поддержанного изменения компонента Нестора и
  определения актуальности в tg-agent; прямые правки файлов ящика не API.
  Не отбрасывать по одному after_id: правки, удаления старых сообщений и
  передачи задач сохраняют самостоятельный смысл. Уже принятые T3 письма
  этим способом не отозвать. Повторный явный subscribe с прежним after_id
  может запрашивать backlog; не заменять эту семантику молчаливым max.
