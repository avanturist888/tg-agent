## gotd: соединение через Start/Stop вместо Run

С gotd v0.164.0 (11.11.2026) у клиента есть жизненный цикл без обёртки в
`Run`: `Client.Start`, `Stop`, `Shutdown`, `Close`, `Wait`, `Done` и
`telegram.Connect` (`telegram/lifecycle.go`, gotd #1948).

Сейчас служба держит соединение так: `serveOnce` (`internal/tgc/shared.go`)
крутит всё внутри `client.Run`, а сторож `watchdog` при зависании ставит
`stalled` и рвёт `Run` через отмену контекста — `Serve` пересоздаёт клиента
(`service_stalled` в аудите). Разовые вызовы без службы идут через
`runShared` / `tgc.Run`.

Посмотреть, упрощает ли новый API:
- пересоздание зависшего соединения (Stop/Shutdown вместо отмены контекста
  и `errStalled`);
- разделяемое соединение `sharedState` (Start один раз, `Done` — сигнал
  смерти вместо своих каналов).

Не срочно: нынешняя обёртка работает. Делать, только если код станет проще.
Сторож и поведение при зависании (`service_stalled`) должны сохраниться.
После правки — живые тесты `go test -tags live -run Live ./internal/core`
и проверка перезапуска службы.
